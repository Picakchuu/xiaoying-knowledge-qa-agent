# 04 · AI 使用记录与验证

## 1. 用在哪里

本项目在与 AI 编码助手的对话中协作完成（模型：DeepSeek 系列；工具：编码 Agent，可读写工作区、跑命令、跑测试）。

| 环节 | 谁做的 | 说明 |
|---|---|---|
| 选题（题 3） | 候选人 | 在四题中选定知识问答，理由写在 `docs/00-plan.md` §1 |
| 需求与验收映射 | 候选人确认，AI 起草 | AI 先把考卷条款逐条对成表格，候选人确认了口径 |
| 方案设计（决策循环 / 五态 / 三级校验 / 内容替换复核） | AI 起草，候选人拍板 | 候选人明确要求"必须加内容替换回归" |
| 合成语料（9 篇文档、3 套语料、3 个替换夹具） | AI 生成 | 纯虚构内容，无真实企业信息 |
| 代码（normalize / tools / validator / agent / llm / cli / http） | AI 生成为主 | 见 §2 的修改记录 |
| 测试 | AI 生成 | 75 条，候选人要求"跑绿再说" |
| 模型与 key | 候选人 | 选定 `deepseek-v4-pro`、自建 `.env`（AI 被安全策略禁止写 `.env`） |
| 仓库与推送 | 候选人 | 建仓、推送、开分支策略由候选人执行（沙箱无法调 GitHub API） |
| 验收与迭代 | 候选人 | 每次验收后给方向（如"开分支再上传"） |

## 2. AI 产出被改掉的地方（改动即证据）

这些不是"AI 一次写对"，而是每轮跑出问题后改的：

| # | 原来 | 改成 | 触发原因 |
|---|---|---|---|
| 1 | Mock 按问题文本查表决策 | 全部判断读 observation（数值、状态、线索） | 否则内容替换后 mock 仍给同样动作，等于自证"预设流程" |
| 2 | `obs = history[-1]` 只喂最后一条观察 | 传完整 history（最近 6 条 + 预算） | 多轮会丢上下文 |
| 3 | `list_versions` 用子串匹配主题 | 改为 2-gram 交集 + 同义词扩展 | 问句「报销需要交纸质发票吗」匹配不到 D08，版本意识用例失效 |
| 4 | `conflict_hint` 按 doc_id 取文本来比相似度 | 按 chunk_id 取，且只在跨文档、共享 ≥2 个 2-gram 时触发 | 同一文档多片段互相覆盖，导致提示漏发 / 误发 |
| 5 | 检索 note 只给分数 | 增加「涉及文档：D01《…（总部专用版）》」 | 真模型第一版只读到 D02，漏掉范围限定版 |
| 6 | 答案里出现 `D08`、`2026-02-01` 等 | 答案不写 doc_id；prompt 要求只写有出处的数值 | 编号里的数字被数值 grounding 判成"无出处" |
| 7 | `openai` SDK | 改 `requests` 直连 `/chat/completions` | 本机 `openai 1.40` 与 `httpx 0.28` 不兼容（`proxies` 参数被移除），且离线装不了新依赖 |
| 8 | `max_tokens=1200`（后改 3000） | 默认 6000，并区分"空内容"错误 | `deepseek-v4-pro` 的 `reasoning_tokens` 把预算吃光，出现空返回 |
| 9 | `ask_user` 只说"存在冲突" | prompt 强制写出双方数值与版本日期 | 真模型第一次追问没给数字，用户没法判断 |
| 10 | 测试用 `tmp_path` | 改写到工作区 `.tmp/` | 本机沙箱临时目录不可写（WinError 5） |
| 11 | 检索结果只给分数和片段 | 命中冲突线索时附带各来源的「适用范围」片段 | 否则模型要额外发 3~4 次检索去查范围，`v4-pro` 单题 249 秒；改后 59 秒 |
| 12 | 冲突豁免看"答案里有没有范围词" | 改为看"问题里有没有限定范围" | 弱模型写"15 天，注意总部专用版仅适用总部"就能蒙混过关 |
| 13 | 无时间上限 | 新增 `--max-seconds`（HTTP 默认 180s） | 推理模型 7 步可拖到 4 分钟，超预算应基于已有证据收尾 |

## 3. 怎么验证 AI 的产出

1. **单元/端到端测试**：`pytest` → 105 passed, 6 skipped（HTTP 端到端在本机沙箱被跳过）（原始输出 `examples/test-results.txt`）；覆盖检索、校验、主循环、上限、内容替换、HTTP 封装、模型客户端（全打桩）。
2. **真实模型评测（可重复）**：`python scripts/real_eval.py` 用真模型跑 14 条验收用例并出报告（`examples/real-eval-deepseek-chat.md`）。最近一次 14/14 通过；正是这轮评测抓出了三个只有真模型才会触发的问题（缺口没回填、工具失败不熔断、JSON 尾部多余内容），见 `docs/03-evaluation.md` §5。
3. **强模型逐条记录**：`examples/case_a2*` 三条 `deepseek-v4-pro` 的 trace。其中 a2c 有一次被校验器真实拦下（`missing_number_grounding`）后自我修正——最能说明"代码在兜底，不是模型说了算"。
4. **内容替换**：把 D01 的 30 天改 45 天、D03 的"不得结转"改"可结转"，答案与冲突值随之改变（C1/C2）。
5. **人工复核点**：每条 quote 都能在 `data/docs` 原文中逐字找到（统计 17/17）；`docs/03-evaluation.md` 的每个结论都能指到具体文件。

## 4. 边界声明

- AI 生成的代码**不等于正确**，本仓库用测试 + 真模型 trace 做交叉验证，但评审仍应自行复核；
- Mock 决策器只验证流程与控制，不证明真实模型的判断质量；
- 真实模型的输出具有随机性，同一问题两次运行步数可能不同（见 `docs/03-evaluation.md` §5）；
- 候选人应在此文档中补充自己实际手改/复核过的部分，并核对与事实一致后再提交。
