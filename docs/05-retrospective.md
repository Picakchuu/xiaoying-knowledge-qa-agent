# 05 · 复盘

## 1. 最难的三件事

### ① 让"能不能结束"由代码说了算

模型很容易自信地说"我答完了"。第一版让模型自己给 `status`，结果它把"两份制度冲突"直接总结成"15 天"。
改成**模型只提议、代码终审**之后才稳住：quote 必须逐字、数值必须有出处、引了两份互斥来源就必须把两个值都写出来。
最后一条（`unhandled_conflict`）是最费劲的——它必须在"拦住偷偷裁决"和"别误杀正常回答"之间取一个保守边界，所以只对**时间类单位 + 跨文档 + 模型自己引用的范围**生效。

### ② 内容替换复核

考卷那句"替换文档内容，核对答案与动作是否改变"是照着"硬编码"打的。
第一版 Mock 用问题关键词 → 动作的映射表，换内容后动作不变，正好踩中。
后来把 Mock 的每个判断都改成读 observation（冲突线索里的数值、检索 note 里的"已过滤"、片段正文），才在换 D01 为 45 天时自动给出 45 vs 15。

### ③ 检索没召回 = 后面全错

真模型第一次跑 A2b（语料含总部专用版）时，只看到 D02 的 15 天和 D01 的 30 天，**根本没意识到还有份总部专用版**，于是判"不可解"。
原因不在模型，在我的检索 note 只给了分数、没给文档清单；标题里的「（总部专用版）」是最强的范围信号。
补了「涉及文档」之后，模型下一步就自己去查了 `D02b#c1`。检索改进的收益比换模型大得多。

## 2. 学习与收获

- **Agent 的可靠性主要来自"可验证的中间状态"**：observation 信封、`conflict_hint`、引用三级校验，都是为了给模型一个"能踩的地面"；
- **prompt 里不能放样例事实**：一旦写了"例如 30 天"，弱模型会直接背答案，内容替换立刻穿帮；
- **推理型模型的预算要按 reasoning_tokens 算**：3000 token 在普通模型够用，在 `v4-pro` 上一次思考就烧完；
- **真模型的非确定性不是 bug**：同一问题步数不同很正常，评测要按"行为区间"而不是"精确步数"来断言；
- **环境限制要如实写进文档**：openai/httpx 冲突、沙箱禁写 `.env`、临时目录不可写——这些不是"没做"，而是"这样绕的"，评审看得出来。

## 4. 下一步（如果还有时间）

1. **换 Embedding + rerank**：`DocStore.search` 是唯一入口，替换后 `conflict_hint` 可改为"同一属性的多来源聚类"，召回长尾会好很多；
2. **把 `conflict_hint` 升级成"属性级"**：现在只覆盖时间类单位，金额/比例类冲突会漏（例如报销额度）；
3. **评测集扩到 50 条并加人工标注**：当前 15 组覆盖验收点，但统计置信度不够；
4. **把 ask_user 做成多轮闭环**：用户回答范围后自动续跑，而不是新开一次会话；
5. **权限隔离**：现实企业里不同员工能看到的制度不同，检索层要加 ACL 过滤（现在假设全域可见）；
6. **延迟优化**：推理型模型单次 1~2.5 分钟，交互场景要换非推理模型或做流式 + 缓存。
